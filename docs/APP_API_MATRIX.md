## Payloads e receipts confirmados

| Operação | Payload de entrada | Resultado observável | O que não significa |
|---|---|---|---|
| `lock lock` via CLI/IPC | nenhum | JSON `{"ok":true}` após execução do handler que solicita lock | não é confirmação de `locked`, `secure`, autenticação nem sucesso de screenshot |
| `SessionService.run` | action id literal do catálogo | sem retorno/exit status; somente efeitos laterais | não reporta sucesso de systemctl/Niri |
| `IdleMonitor` transição | estado idle do monitor Wayland | efeitos lock/DPMS/suspend listados | não é acknowledgment de efeito downstream |
| `PolkitService.submit` | secret transitório | encaminha somente se o flow atual requer resposta | não é aprovação; conclusão não tem resultado público |
| `PolkitService.cancel` | sem payload | solicita cancelamento se flow atual existe e não completed | não prova que request terminou cancelado |
| `MonitorService.load` | nenhum | atualiza snapshot por read-only query; pedidos durante execução coalescem em 1 reload | não é comando IPC |
| `CompositorService.load` | nenhum | inicia `niri --version` | não é mutação e não expõe exit receipt |

## Fixtures canônicas desta rodada

- `docs/fixtures/compositor_service.loaded.json`: shape observado após stdout não vazio; não cobre erro/exit.
- `docs/fixtures/monitor_service.loaded.json`: payload normalizado pelo helper, valores inteiramente sintéticos; preserva chaves/defaults do script.
- `docs/fixtures/session_actions.json`: catálogo literal da fonte, incluindo ordem, glyphs, labels e destructive.
- **Sem fixture oficial ainda:** Idle (estado inicial de isIdle não definido), Lock (múltiplos estados dependem runtime; segredo proibido), Polkit (validade/correlação/terminal ainda não fechadas). Fixtures não validam comportamento por si.

Eventos `FontChanged`, `EmojiChanged`, `MachineChanged`, `VersionChanged`, `SunsetChanged` e `ApplicationsChanged` são envelopes Rust propostos para publicar snapshots observáveis; não são nomes de sinais emitidos pelo original. Os adapters não têm `onError` uniforme e vários processos não têm receipt de conclusão; não converter ausência de observação em sucesso/falha.

Fixtures sintéticas dos payloads de script com schema definido: `docs/fixtures/fonts.index.json`, `machine.report.json` e `applications.index.json`. Não cobrem lifecycle/erro. Não há fixture para Emoji, Version ou Sunset nesta rodada porque estados persistidos/terminais ainda têm lacunas; ver `APP_API_REVIEW.md`, rodada 4.
